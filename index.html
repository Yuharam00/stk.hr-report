STEP 01

업로드 파일 준비

메인 HTML 파일 이름을 정확히 맞추고, 이미지가 있다면 폴더 구조를 정리합니다.

파일명 규칙

정상index.html
오류 index.html.html Index.html index.HTML

폴더 구조

최상단index.html
images 폴더logo.png, chart01.png, background.jpg …

준수 사항

  • HTML 안의 이미지 경로는 images/logo.png처럼 상대경로를 사용합니다.
  • C:\Users\... 형태의 개인 PC 경로는 다른 사람에게 표시되지 않습니다.
  • 브라우저 업로드 파일은 개별 25MiB 이하가 안전합니다.

업로드 전 공개정보 점검

  • 임직원 이름·연락처·사번
  • 급여·평가·징계·건강정보
  • 계약조건·매출·원가 등 회사 기밀
  • 비밀번호·API 키·내부 시스템 주소
⚠
주의 — GitHub Pages는 인터넷 공개 페이지입니다. 링크를 받은 사람만 보는 사내 전용 문서함이 아닙니다.
STEP 02

새 저장소 생성

실행 순서

  1. GitHub 오른쪽 위 + 메뉴에서 New repository를 선택합니다.
  2. Owner는 Yuharam00을 선택합니다.
  3. Repository name에 영문 소문자와 하이픈을 사용해 입력합니다.
  4. 필요한 설정을 확인한 뒤 Create repository를 클릭합니다.

권장 설정

VisibilityPublic — 단, 민감정보가 전혀 없는 경우에만
Add READMEOff
.gitignoreNo .gitignore

STEP 03

HTML 파일 업로드

실행 순서

  1. 저장소의 Code 화면에서 Add file → Upload files를 선택합니다.
  2. index.html과 필요한 images 폴더를 끌어다 놓습니다.
  3. 업로드 목록에서 파일명과 폴더 구조를 확인합니다.
  4. Commit message에 변경 내용을 간단히 입력합니다. 예: Initial upload of HR report
  5. Commit changes를 클릭합니다.
✓
확인 — Code 화면의 파일 목록 최상단에 index.html이 보여야 합니다.

파일 업로드 직후 체크

  • 파일명이 index.html인가?
  • index.html이 폴더 안이 아니라 최상단에 있는가?
  • images 폴더도 함께 올라갔는가?
  • 민감정보가 포함되지 않았는가?
STEP 04

GitHub Pages 활성화

실행 순서

  1. 저장소 상단의 Settings를 클릭합니다.
  2. 왼쪽 메뉴 Code and automation 영역에서 Pages를 클릭합니다.
  3. Build and deployment의 Source에서 Deploy from a branch를 선택합니다.
  4. Branch는 main, 폴더는 /(root)를 선택합니다.
  5. Save를 클릭합니다.

권장 설정

SourceDeploy from a branch
Branchmain
Folder/(root)

정상 표시 문구

아래 문구가 보이면 정상입니다.

"currently being built from the main branch" 또는 "Your site is live at ..."

ℹ
Save 버튼이 회색이면 이미 같은 설정이 저장된 상태일 수 있습니다. 별도로 다시 누를 필요가 없습니다.

실행 순서

  1. 수정된 파일의 이름을 index.html로 확인합니다.
  2. 저장소 Code 화면에서 Add file → Upload files를 선택합니다.
  3. 동일한 index.html을 업로드하고 Replace 여부를 확인합니다.

STEP 07

HTML 보고자료가 여러 개인 경우

✓
핵심 — GitHub Pages는 저장소에서 한 번만 활성화하면 됩니다. 이후 업로드한 HTML 파일은 각각의 파일·폴더 경로로 자동 공개되며, 파일마다 Pages 설정을 반복할 필요가 없습니다.

폴더 구조 예시

저장소 최상단index.html — 보고자료 목록 또는 최신 보고자료
weekly-2026-08-07/index.html, images/ — 8월 1주차 보고자료
weekly-2026-08-14/index.html, images/ — 8월 2주차 보고자료
recruitment-report/index.html, images/ — 채용 현황 보고자료

각 보고자료의 개별 접속주소

메인 페이지https://yuharam00.github.io/stk-hr-report/
8월 1주차https://yuharam00.github.io/stk-hr-report/weekly-2026-08-07/
8월 2주차https://yuharam00.github.io/stk-hr-report/weekly-2026-08-14/
채용 현황https://yuharam00.github.io/stk-hr-report/recruitment-report/
ℹ
주소 원리 — 폴더 안에 index.html이 있으면 주소 끝에 index.html을 쓰지 않아도 됩니다. 예: /weekly-2026-08-07/

새 보고자료 추가 및 활성화 절차

  1. 새 보고자료용 폴더명을 영문 소문자·숫자·하이픈으로 정합니다. 예: weekly-2026-08-21
  2. 해당 보고자료의 메인 파일명을 index.html로 바꾸고, 전용 images 폴더와 함께 준비합니다.
  3. 저장소 Code 화면에서 Add file → Upload files를 선택합니다.
  4. 준비한 보고자료 폴더 전체를 업로드하고 Commit changes를 클릭합니다.
  5. 1~5분 후 저장소 주소 뒤에 폴더명을 붙여 접속합니다.
  6. PC·모바일과 시크릿 창에서 확인한 뒤 해당 보고자료의 개별 URL을 공유합니다.
⚠
중요 — 기존 Settings → Pages의 main / (root) 설정은 그대로 둡니다. 새 HTML을 추가할 때마다 Pages 메뉴에서 다시 활성화할 필요가 없습니다.

같은 폴더의 보고자료를 수정할 때

  1. 수정 대상 폴더를 확인합니다. 예: weekly-2026-08-14
  2. 그 폴더 안의 index.html과 필요한 이미지 파일만 교체합니다.
  3. Commit changes 후 1~5분 기다린 뒤 기존 개별 URL을 새로고침합니다.

폴더명을 바꾸지 않으면 조직장에게 이미 공유한 주소를 계속 사용할 수 있습니다.

파일명으로 직접 구분하는 방법 (대안)

파일명report-2026-08-07.html
접속주소https://yuharam00.github.io/stk-hr-report/report-2026-08-07.html
ℹ
권장안 — 이미지 파일이 있거나 보고자료가 계속 늘어난다면 파일명 방식보다 '보고자료별 폴더 + index.html' 방식이 정리와 수정에 유리합니다.

여러 보고자료 운영 시 주의사항

  • 폴더명과 파일명에는 한글·공백 대신 영문 소문자·숫자·하이픈을 사용합니다.
  • 각 보고자료의 이미지는 해당 폴더 안 images 폴더에 보관해 서로 덮어쓰지 않게 합니다.
  • 기존 폴더를 삭제하면 그 폴더의 공유 URL도 즉시 사용할 수 없게 됩니다.
  • 최상단 index.html에 보고자료 목록과 링크를 만들면 과거 자료를 한 화면에서 찾기 쉽습니다.
  • Public 저장소에서는 과거 보고자료도 인터넷에 공개되므로 개인정보·회사 기밀을 계속 점검합니다.

파일명을 직접 수정하는 방법

  1. Code 화면에서 잘못된 파일을 클릭합니다.
  2. 오른쪽 위 연필 아이콘(Edit this file)을 클릭합니다.
  3. 상단 파일명에서 불필요한 확장자를 삭제합니다.
  4. Commit changes... → Commit changes를 클릭합니다.
⚠
실제 오류 사례 — index.html.html → index.html
